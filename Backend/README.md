# Lens Backend

Four AWS Lambda functions implement the Lens RAG pipeline. Each lives in
its own directory with a `lambda_function.py` (the entry point AWS Lambda
expects) and a `requirements.txt`.

## Directory layout

```
Backend/
├── LlamaGet/        POST /llamaGet         — open a session, return presigned upload URL
├── LlamaParse/      (S3 trigger)           — chunk + embed PDF, persist to DynamoDB
├── LlamaQuery/      POST /query            — RAG answer for a question against a session
├── LlamaStatus/     GET  /sessions/{id}    — read the parse status of a session
└── tests/           pytest suite (moto + monkeypatched OpenAI)
```

## Session lifecycle

```
AWAITING_UPLOAD ──(upload to S3)──▶ PROCESSING ──▶ READY_FOR_QUERY
                                             └────▶ ERROR (error field is set)
```

LlamaGet writes the initial row. LlamaParse transitions to PROCESSING when
it starts and to READY_FOR_QUERY or ERROR when it finishes. LlamaStatus
exposes the row to the frontend so the UI can poll instead of guessing.

## Environment variables

| Function    | Required                                           | Optional                                                        |
|-------------|----------------------------------------------------|-----------------------------------------------------------------|
| LlamaGet    | `BUCKET_NAME`, `TABLE_NAME`                        | `PRESIGN_EXPIRES_SECONDS` (default 3600)                        |
| LlamaParse  | `BUCKET_NAME`, `SESSIONS_TABLE`, `CHUNKS_TABLE`, `OPENAI_API_KEY` | `EMBEDDING_MODEL`, `CHUNK_SIZE`, `CHUNK_OVERLAP` |
| LlamaQuery  | `SESSIONS_TABLE`, `CHUNKS_TABLE`, `OPENAI_API_KEY` | `EMBEDDING_MODEL`, `LLM_MODEL`, `DEFAULT_TOP_K`, `LLM_MAX_TOKENS`|
| LlamaStatus | `SESSIONS_TABLE`                                   | —                                                               |

## DynamoDB schema

**sessions** — partition key `sessionId` (string).

| Field      | Type      | Notes                                                  |
|------------|-----------|--------------------------------------------------------|
| sessionId  | S         | UUID generated by LlamaGet                             |
| status     | S         | AWAITING_UPLOAD / PROCESSING / READY_FOR_QUERY / ERROR |
| s3Key      | S         | `uploads/<sessionId>.pdf`                              |
| createdAt  | S         | ISO-8601 UTC                                           |
| error      | S         | Present only when status = ERROR                       |

**chunks** — partition key `sessionId` (string), sort key `chunkId` (string).

| Field      | Type      | Notes                                                  |
|------------|-----------|--------------------------------------------------------|
| sessionId  | S         | Matches sessions.sessionId                             |
| chunkId    | S         | `chunk_0`, `chunk_1`, …                                |
| text       | S         | Plain text of the chunk                                |
| embedding  | L<Number> | Embedding vector — stored as Decimal in DynamoDB       |
| order      | N         | Position of the chunk in the source document          |

## Packaging for Lambda

Each function is deployed as a zip. Install its deps into the function
directory and zip the contents:

```bash
cd LlamaGet      && pip install -r requirements.txt -t .   && zip -r ../LlamaGet.zip .       && cd ..
cd LlamaParse    && pip install -r requirements.txt -t .   && zip -r ../LlamaParse.zip .     && cd ..
cd LlamaQuery    && pip install -r requirements.txt -t .   && zip -r ../LlamaQuery.zip .     && cd ..
cd LlamaStatus   && pip install -r requirements.txt -t .   && zip -r ../LlamaStatus.zip .    && cd ..
```

Better: do this in CI from a clean directory. The `tests/` folder is not
part of any deployment package.

## Running the tests

```bash
pip install -r tests/requirements.txt
pytest
```

The suite uses `moto` to mock S3 + DynamoDB in-memory and patches the
OpenAI client per-test, so no AWS credentials and no API key are needed.

## Chunking

LlamaParse splits text on paragraph boundaries (`\n\n`), greedily packing
paragraphs into chunks up to `CHUNK_SIZE` characters. Each chunk after the
first carries the last `CHUNK_OVERLAP` characters of its predecessor so
sentences that straddle the boundary don't get lost. Paragraphs larger
than `CHUNK_SIZE` are hard-sliced with the same overlap.

This is intentionally simpler than a fully recursive splitter — easy to
read, easy to reason about, and good enough for the legal contracts the
tool is aimed at.

## API shapes

| Method | Path                    | Body                                          | Response                                            |
|--------|-------------------------|-----------------------------------------------|-----------------------------------------------------|
| POST   | `/llamaGet`             | —                                             | `{ sessionId, uploadUrl }`                          |
| GET    | `/sessions/{sessionId}` | —                                             | `{ sessionId, status, error? }`                     |
| POST   | `/query`                | `{ sessionId, query, topK? }`                 | `{ sessionId, answer, metrics }`                    |
